# B506 selected-parameter API results

This software API companion addresses the selected OP11 parameter union only.
The [public native B506 contract](../protocols/vaillant/ebus-vaillant-B506.md#b5-06-11-end-of-line-test-service-shape)
keeps physical parameter framing and effects Unknown. The selection below is a
Hypothesis supplied to a pure library contract, not new native wire evidence.
No enclosing offset, termination, minimum transport extent or maximum is established.
The supplied value is already isolated. Device families and variants are opaque;
no view token, candidate label or successful call grants permission or qualification.

```go
package vaillant

func Ab03Ao03Interpret(ab03ao03Input json.RawMessage) (json.RawMessage, error)
```

The signature specifies the library API; this page neither imports nor supplies
its implementation. It is independently testable without an AO03 code merge.
New Go names use Ab03Ao03 or ab03ao03 (Go tests use TestAb03Ao03).
There is no global cache, catalog, Entries/Lookup API, registration, pending-API
import, runtime call site, executor, scan policy or UI change. Existing eBUS MCP
compatibility and GraphQL parity are unaffected; no new endpoint is specified.

## JSON shapes and selection

Input is an object with required object members `context` and `fields`, and an
optional object `arguments`. Context requires integer `primary`, `secondary`,
`operation`, string `direction` and explicit string `view`. Additional context
keys, including opaque `family` and `variant`, survive unchanged, recursively.
Fields maps every supplied name to an array of integer bytes in 0..255; unknown
fields and every tail byte survive in `raw`. No scalar argument is defined for
this view, so supplied arguments may only be `{}`. Missing arguments stay absent.
Malformed JSON, duplicate object keys at any depth, wrong kinds, missing required
objects/context selectors and invalid bytes return an error with no successful
result. Booleans and floating-point tokens are not integer bytes or selectors.

Only the exact tuple `(181, 6, 17, "request", "parameter-union")` selects this
software view. Other well-typed selector values return raw-only `Unknown` with
empty semantic fields. Family labels, names, payload lengths and array position
never select an interpretation. The key is the supplied one-byte `fields.key`;
`fields.value` is the isolated byte sequence. Keys are decimal.

| Decimal key | Selected value | Complete result |
|---|---|---|
| 0, 1, 2, 4, 5 | Opaque bytes through supplied end | Raw array; no number or text conversion |
| 3, 6, 7, 8, 9, 32, 33, 34, 35, 36, 37 | Exactly one raw byte | Unsigned byte number, no unit or physical meaning |
| 10 | Exactly one Boolean byte | 0: number 0, label no; 1: number 1, label yes |
| Other keys | No alternative | Raw-only Unknown; no nearest-key fallback |

## Result, presence and grades

Output contains deep independent copies of `context`, `raw` (all input fields),
and `arguments` if supplied, plus `state`, semantic `fields`,
`physical: "Unknown"` and `qualified: false`. Under this view the only semantic
field is `fields.value`, with its own raw array. Complete semantic fields have
`state: "Hypothesis"`. Complete scalar and mapped Boolean fields additionally
have `number` and `calculation: "Proven"`; this exact byte calculation never
promotes the family interpretation. Opaque fields have no number or label.
No flags, reserved bits or candidate domain are defined for this selected view.
The wider API permits optional `flags`, `reserved` or `candidate_domain` only
where a contract explicitly defines them. An outside-domain carrier may retain
an explicitly defined number with `candidate_domain: false`; none is defined here.
Incomplete, unmapped, unit-conflict and unknown-order fields have no number.

A successful complete selection has top-level state `complete`. Missing or empty
key, a multi-byte key, or a missing value yields `partial`, with no semantic value
field. A present empty scalar/Boolean value yields a value field with
`state: "incomplete"`; two or more bytes yield `state: "width-conflict"`, retaining
all bytes with no number. These are `partial`, never truncation successes.
Boolean byte 2 (and any other unmapped byte) yields value state `unmapped` and
top-level `Unknown`. An unknown key or selector is explicitly `Unknown`, even
when other fields are incomplete. Unknown raw siblings do not erase a valid value.
General partial results retain complete independent fields; this view defines
only one semantic field. Empty opaque bytes are a complete representable supplied
sequence, **not evidence of accepted empty traffic**. Missing, empty and explicit
zero remain distinct after JSON round trips. Native production-test admission,
effects, persistence and complete physical adaptation remain Unknown in all cases.

Returned nested arrays/objects, input buffers and later calls share no mutable
storage. Mutating one result or the original input after a call cannot alter
another result. Documentation checks cannot establish Go memory ownership;
production tests must establish that separately against the implementation.
